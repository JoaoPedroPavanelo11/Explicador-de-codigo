#09  feat(auth): implementa cadastro, login e JWT com refresh token rotativo
     3a48262 · 20/11/2026 14:09 · branch feature/auth

     O QUE MUDOU
     Usa @nestjs/authentication: guard global (todas as rotas exigem
     login, exceto @Public), hash scrypt, verificação em tempo constante,
     access token de 15 min e refresh token em cookie httpOnly +
     SameSite=Strict + path /api/auth. Implementa um RefreshTokenStore
     próprio no Postgres (tabelas refresh_tokens e
     revoked_token_families), guardando apenas o SHA-256 dos tokens.
     Regras de senha no cadastro e rejeição de campos desconhecidos.

     QUAL PROBLEMA RESOLVE
     Resolve vários problemas de segurança de uma vez: (1) 'fechado por
     padrão' evita esquecer de proteger uma rota nova; (2) o login
     responde no mesmo tempo para e-mail inexistente e senha errada,
     impedindo descobrir quais e-mails existem; (3) o cookie httpOnly
     impede que um script malicioso (XSS) leia o refresh token; (4) com
     rotação, um refresh token roubado e reutilizado revoga toda a família
     — o ladrão perde o acesso; (5) campos extras no body (ex.: 'role':
     'admin') são recusados.

#22  feat(ingestion): recebe código por .zip e por repositório público do GitHub
     11dba2a · 20/11/2026 14:27 · branch feature/analysis-api

     O QUE MUDOU
     zip-extractor.ts: extração em memória com yauzl, contando bytes reais
     (zip bomb), recusando entradas com ../ (zip slip), ignorando links
     simbólicos e limitando entradas. github-fetcher.ts: valida
     dono/repositório com regex, monta a URL de download num host fixo
     (codeload.github.com), não segue redirects, limita tamanho em
     streaming e tempo. 16 testes com um zip montado em memória.

     QUAL PROBLEMA RESOLVE

     zip slip pode sobrescrever arquivos; uma URL arbitrária permitiria
     SSRF (usar o servidor para acessar a rede interna, como
     169.254.169.254). Cada um desses ataques tem um teste.

#24  feat(queue): processa análises em segundo plano com BullMQ e Redis
     22e28c2 · 20/11/2026 14:31 · branch feature/analysis-api

     O QUE MUDOU
     AnalysisProcessor (concorrência 2) lê o job, extrai os arquivos, roda
     o motor e salva o resultado. Erros do usuário não são re-tentados
     (UnrecoverableError); erros internos têm 2 tentativas com backoff e
     mensagem genérica. O .zip temporário é sempre apagado. Usa uma

     da requisição HTTP travaria a API e daria timeout. Com a fila, a API
     responde 202 na hora. Mensagens genéricas evitam vazar detalhes
     internos (stack traces) para o usuário.
